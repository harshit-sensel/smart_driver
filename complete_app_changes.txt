SECTION 2: DASHBOARD TILE & MOVEMENT LOCKSCREEN (LockScreenActivity)
================================================================================
1. Audio Voice Warning Files (Scoped Storage Fix for Android 10 to 16):
   - Change voice alert download and playback path from:
       Environment.getExternalStorageDirectory() + "/driverapp/"

     so warnings play even before custom audio download finishes.
   - Files: LockScreenActivity.java (DownloadFileFromURL & MediaPlayer calls)

2. Screen Wakeup & Keyguard Dismissal (Android 8 to 16):
   - In AndroidManifest.xml under <activity android:name=".LockScreenActivity">:
       android:showWhenLocked="true"
       android:turnScreenOn="true"
   - In LockScreenActivity.java (onCreate):
       if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O_MR1) {
           setShowWhenLocked(true);
           setTurnScreenOn(true);
           KeyguardManager km = (KeyguardManager) getSystemService(Context.KEYGUARD_SERVICE);
           if (km != null) km.requestDismissKeyguard(this, null);
       } else {
           getWindow().addFlags(
               WindowManager.LayoutParams.FLAG_SHOW_WHEN_LOCKED |
               WindowManager.LayoutParams.FLAG_TURN_SCREEN_ON |
               WindowManager.LayoutParams.FLAG_DISMISS_KEYGUARD
           );
       }
       getWindow().addFlags(WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON);

3. Single Instance / Bring to Front:
   - In SaveMyAppsService.java when speed > 10 km/h:
       i.setFlags(Intent.FLAG_ACTIVITY_NEW_TASK | Intent.FLAG_ACTIVITY_REORDER_TO_FRONT);

SECTION 3: CAMERA PHOTO CAPTURES & FILE SHARING (Android 7 to 16)
================================================================================
1. Package Visibility Filter (Android 11 to 16):
   - Issue: In Daily_Checklist1.java:
       takePictureIntent.resolveActivity(getPackageManager())
     On Android 11+, this returns NULL unless <queries> is in AndroidManifest.xml,
     causing the Camera to silently fail to open!
   - Fix in AndroidManifest.xml:
       <queries>
           <intent>
               <action android:name="android.media.action.IMAGE_CAPTURE" />
           </intent>
           <intent>
               <action android:name="android.intent.action.VIEW" />
               <data android:mimeType="application/pdf" />
           </intent>
       </queries>

2. FileProvider Authority & Path Alignment:
   - Issue: AndroidManifest.xml currently has "com.example.android.fileprovider",
     while Daily_Checklist, Unload_QTY, DeviationReport, and NotifyTransporter call
     getPackageName() + ".provider" ("com.sensel.driverapp.provider").
     Also provider_paths.xml lacks <external-files-path>, throwing an immediate
     IllegalArgumentException crash when taking photos.
   - Fix in AndroidManifest.xml:
       android:authorities="${applicationId}.provider"
   - Fix in Daily_Checklist1.java (Line 762):
       Change "com.example.android.fileprovider" to getPackageName() + ".provider"
   - Fix in app/src/main/res/xml/provider_paths.xml:
       <paths>
           <external-files-path name="external_files_dir" path="." />
           <cache-path name="cache_dir" path="." />
           <external-path name="external_files" path="." />
       </paths>

3. Driver Safety Manual PDF Viewer (JavaScriptInterface.java):
   - Issue: ShowPDF() uses Uri.fromFile(file), crashing on Android 7+ with
     FileUriExposedException.
   - Fix: Use FileProvider.getUriForFile() with Intent.FLAG_GRANT_READ_URI_PERMISSION
     and read from context.getExternalFilesDir(null).

SECTION 6: PERMISSIONS & UI STABILITY
================================================================================
1. Runtime Notifications Permission (Splash.java on Android 13+):
   - Request Manifest.permission.POST_NOTIFICATIONS on Android 13+ (API 33+)
     instead of deprecated WRITE_EXTERNAL_STORAGE.

2. Screen Overlay Permission / Display Over Other Apps (Gridmenu.java on Android 10 to 16):
   - Issue: The permission <uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
     is declared in the Manifest, but on Android 10+, the OS will NOT allow background
     services (SaveMyAppsService and MyService1) to pop the LockScreenActivity or App_lock
     over other apps unless the user explicitly grants "Display over other apps" in Settings.
   - Minimal Fix in Gridmenu.java (onResume / checkSpecialPermissions):
     if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.M && !Settings.canDrawOverlays(this)) {
         // Show a polite dialog explaining that 'Display over other apps' is needed
         // to lock the phone while moving for safety, and launch:
         Intent intent = new Intent(Settings.ACTION_MANAGE_OVERLAY_PERMISSION,
                 Uri.parse("package:" + getPackageName()));
         startActivity(intent);
     }

3. ERV Search Crash Prevention (ERV_Driver.java):
   - Use androidx.appcompat.R.id.search_src_text with null check to prevent NPE.
